JOREK

Modified

October 25, 2026

Purpose

JOREK is a nonlinear extended-MHD code with a flux-aligned finite-element grid that includes the X-point, scrape-off layer and divertor. The Tokamak Toolkit uses it as an external, open (Tier A) reference for MHD stability, which its transport loop does not model. It serves brief invariants 1–3: JOREK runs outside JAX, is never called inside compiled code, and is never a runtime dependency of a surrogate.

Scope

Owner decision OQ-37:

step what status
A linear pedestal-stability scans over toroidal mode number, ITER hybrid first, then MAST-U ITER: case (a) closed on the time-step check; case (b) running (J5)

C a surrogate of a JOREK quantity behind a guard decided after A’s cost is known
D nonlinear ELM crash runs reference runs only, later
E disruptions, vertical displacement events, shattered pellet injection outside the brief; deferred

Licence: GNU LGPL v3 or later. JOREK is executed as a separate program and is not vendored, so the toolkit’s own licence is unaffected. Results that use JOREK cite the JOREK overview papers and acknowledge the JOREK team (bottom of this page).

Build

JOREK is built from source at a pinned commit; there are no tagged releases. The build uses GNU Fortran 12.3 and OpenMPI 4.1 with OpenBLAS, ScaLAPACK, FFTW, HDF5, METIS and ParMETIS. The sparse direct solver is our own MUMPS 5.7.3 build, with PORD, METIS and ParMETIS orderings. Binaries are compiled for x86-64-v3, so the same binary runs on the Intel login nodes and the AMD compute nodes. util/config.sh fixes the physics model and toroidal resolution at compile time and edits a source file, so each configuration is built in its own git worktree.

Build notes
  • MUMPS: build the real and complex libraries one after the other. A parallel build of both races on Fortran module files.
  • GNU Fortran rejects a space between a namelist name and its subscript (name (1) = …), which Intel Fortran accepts. Upstream inputs are rewritten without it; values are unchanged.
  • The code’s default solver is STRUMPACK. Runs with MUMPS set use_mumps = .t. and use_strumpack = .f. in the namelist.
  • eqdsk2jorek needs the DIERCKX (FITPACK) spline library, built from netlib with double-precision default reals.
  • With more than one toroidal harmonic, JOREK needs at least two MPI ranks.

Regression checks. These use JOREK’s own cases and the reference data the JOREK team publishes, so the check does not depend on toolkit code (3 of 4 upstream regression cases reproduce their public reference data: MAST-U grid and equilibrium (largest difference 2.0e-5, tolerance 1e-4), MAST equilibrium with coils (1.2e-10), and one implicit tearing-mode step (4.1e-13, tolerance 1e-12); the full-MHD kink case was not run because its upstream input is out of date for this code versionC-210). On the compute nodes, one job repeated them and measured the step cost (all three regression cases pass on a 256-core AMD node; one implicit step on the MAST-U X-point grid (8050 elements, toroidal modes n = 0 and 1) takes 5.8 s at 2 ranks x 16 threads, 6.7 s at 4 x 32 and 8.1 s at 2 x 64; the whole job used 22.4 core-hoursC-211).

Unit conversion and input files

tkit.adapters.jorek (Tier A, host side) converts between SI/eV and JOREK’s normalised units. With \(n_0 = \texttt{central\_density}\cdot10^{20}\,\mathrm{m^{-3}}\) and \(\rho_0 = \texttt{central\_mass}\cdot m_\mathrm{u}\, n_0\):

\[ n = \rho\, n_0,\qquad T_\mathrm{eV} = \frac{T}{e\,\mu_0\, n_0},\qquad t_\mathrm{SI} = t\,\sqrt{\mu_0\rho_0},\qquad \gamma_\mathrm{SI} = \frac{\gamma}{\sqrt{\mu_0\rho_0}}, \]

using the constants of the pinned JOREK version (models/constants.f90), not CODATA. Single-temperature models evolve \(T = T_e + T_i\), with \(p = \rho T/\mu_0\). The toroidal mode number of Fourier component \(k\) (1-based) is \(\lfloor k/2\rfloor\, n_\mathrm{period}\).

What the adapter covers:

  • Profile files are two bare numeric columns (\(\psi_N\), value). JOREK’s reader stops silently at the first unparseable line, so the writer emits no header and reads every file back for an exact match.
  • Namelists are written one entry per line, with full precision and no space before subscripts. Index ranges such as fbnd(2:4) and both quote styles are supported. A parser for JOREK inputs is included.
  • Energy reader. It reads magnetic and kinetic energy per Fourier component from a restart file, and checks the array shapes and that the stored time unit matches the normalisation.
  • Growth rates are a least-squares fit of \(\tfrac12\ln E\) against time over a window the caller must give. No default window is offered, because choosing the linear phase is part of the analysis.

Correctness. - The conversion matches the units JOREK stored in three restart files (time and resistivity units computed by the toolkit match the values JOREK stored in three restart files to 1e-15 relativeC-213). - A rewritten MAST-U input gives an identical restart file (the MAST-U input (356 entries) parsed and rewritten by the toolkit gives, with one thread, a restart file identical in every dataset to a run of the original inputC-214). - The tests are in 26 tests pass in normal and Tier-A-only modes: unit conversion, profile files, namelists, the energy reader, and the runner with fake executables (snapshots, retry, timeout, provenance)C-215.

Design decisions. - Conversion only, deliberately. JOREK’s own scripts hard-code physics choices: the scrape-off-layer extension, diffusivities, resistivity and grid sizes. Here each of them is a required input, so it reaches the owner as a decision (OQ-39). - Native HDF5, not IMAS output. JOREK’s IDS writer needs the IMAS Fortran access layer, and its Python scripts use the pre-2.0 IMAS API.

Run wrapper

tkit.datasets.jorek_run runs one case in a new directory:

  1. It snapshots the executable and every input read-only, and verifies any input provenance.
  2. Each attempt gets fresh working copies. The namelist goes on standard input, and the launcher sets MPI ranks and OpenMP threads explicitly.
  3. The process group is killed at the timeout, and partial output is kept.
  4. The outcome is classified: completed, solver aborted, grid set-up abort, JOREK error, non-zero exit or timeout.
  5. A provenance record is written beside every retained file. result.json records ranks, threads and whether the run is bitwise repeatable.

Two measured JOREK properties shape it (an assertion in the element search tree aborts 3 of 8 grid set-up runs at 8 OpenMP threads and 0 of 8 at 1 thread; two 4-thread runs of the same input differ at round-off, while 1-thread runs repeat bit for bitC-212): - Threaded runs are not bitwise repeatable, so only one-thread runs are marked repeatable. - Threaded runs intermittently abort on an assertion in the element search tree during grid set-up, before any time step. The wrapper retries only that case, only before the first step, and keeps every attempt.

On the real program the wrapper reproduces a manual run exactly. A completed run is not physical acceptance.

Post-mortem: a GMRES abort recorded as a completed run (2026-10-24)
  • What was written, and what was correct. The wrapper classified any run that exited with code 0 as completed, unless it had timed out or hit the known grid set-up assertion. JOREK stops a run whose iterative linear solver (GMRES) fails to converge, but it exits with code 0. The correct classification is a separate outcome, solver_aborted: the energies up to the abort are valid data, and the run is not retried, because a retry would fail the same way.
  • What it looked like from inside. All eight linear runs of the first case (a) scan ended this way and were recorded as completed (8 of 8 case (a) runs ended on the GMRES abort with exit code 0; a test now checks that such a run is recorded as solver_aborted and not retriedC-230). Every wrapper check passed: the exit code was 0, the output files existed, and the provenance records were complete. None of them reads the end of the log.
  • What caught it. The growth-rate analysis: the energy traces ended at different times, and each run’s log ended with the abort message. The analysis reads JOREK’s own output, not the wrapper’s status, so it is independent of the classifier.
  • Before and after. Before: 8 of 8 runs completed. After: 8 of 8 solver_aborted, energies kept.
  • What changed. The abort string is now an outcome of its own. The test test_gmres_abort_with_exit_zero_is_not_completed runs a stub JOREK that prints the abort and exits 0, and checks that the run is classified solver_aborted and is not retried.
  • Blast radius. None published: no growth rate had been reported from these runs. The abort follows the linear phase in every run, so the growth data stay usable.

ITER hybrid equilibrium

Input: the ITER hybrid EQDSK distributed with TORAX (COCOS 2, \(I_p\) 11.77 MA, \(B_0\) 5.3 T). A JOREK stability run starts from an equilibrium JOREK solves itself, from a boundary, a pressure profile and FF′. The acceptance tolerance (OQ-39, decision 2) is q within 2% of the source over \(\psi_N\) 0.1–0.95, and \(I_p\) within 1%, before any stability run.

Current route: fixed boundary on the EQDSK separatrix. The boundary is the EQDSK separatrix itself: 300 points on the flux surface \(\psi = \psi_\mathrm{bnd}\), ordered by angle about the geometric centre, with no X-point and a polar flux-aligned grid (scripts/jorek/iter_lcfs_input.py). Pressure and FF′ are those of the first route below. JOREK model303 solves the fixed-boundary equilibrium on one core.

grid (\(n_\mathrm{flux}\) × \(n_\theta\)) result accepted
40 × 64 I_p −1.38%, largest q difference 1.1%: fails the current toleranceC-220 no
80 × 128 I_p −0.93%, largest q difference 1.1%, q 4.668 against 4.668 at psi_N 0.95: passes the tolerance of q within 2% and I_p within 1%C-221 yes
160 × 256 I_p −0.20%, largest q difference 1.1%: passesC-222 yes

The largest q difference, 1.1%, is in the core and is the same on all three grids. Edge q agrees to better than 0.3%. The current deficit shrinks with resolution but is not yet in a clean asymptotic regime. The 80 × 128 grid is used for the n-scans and 160 × 256 for the doubled-resolution check.

Limitation. A fixed boundary at the separatrix acts as an ideal conducting wall there, with no vacuum region. Peeling modes, which need one, are artificially stabilised. All growth rates on this page carry this limitation.

First route: eqdsk2jorek (2026-10-16). eqdsk2jorek produced the boundary, FF′ and namelist after three changes: - the spline smoothing was raised from 1e-6 to 3e-5, the smallest value for which the fit succeeds; the RMS fit error is about 2e-7 Wb; - the converter’s pressure continuation went to −10 Pa outside the separatrix, because the EQDSK pressure there is 0 and the converter’s edge value is 10 Pa; - the temperature file was therefore written by the toolkit: EQDSK pressure inside, a 10 Pa floor outside, check-only.

Its result, JOREK solving the ITER hybrid equilibrium from the TORAX EQDSK matches its safety factor q to 0.4% (median) for normalised flux 0.1-0.5, but is 3.6% high for 0.5-0.9 and 5.8% high for 0.9-0.95 (q 5.12 vs 4.67 at 0.95); plasma current 12.06 vs 11.77 MAC-216 (superseded by C-221), failed the tolerance at the edge.

Post-mortem: the edge mismatch came from the converter’s boundary (2026-10-16)

  • What was written, and what was correct. eqdsk2jorek builds a free-boundary-style domain from a default ITER contour outside the wall, and takes ψ on that contour from the EQDSK. That is correct only if the EQDSK grid covers the contour. The TORAX EQDSK comes from a fixed-boundary CHEASE solve: its R–Z grid holds no X-point (\(|\nabla\psi|\) has no zero inside it, and a minimiser leaves the grid), and 187 of the contour’s 257 points lay outside the grid. ψ there was extrapolated, and JOREK built its own X-point and separatrix, enclosing a larger plasma than the EQDSK’s. The correct boundary for this source is its own separatrix.

  • What it looked like from inside. The converter ran without error once the smoothing was raised, the sign conventions all came out right, and core q matched to 0.4%. Only edge q and the current were off, by a few percent, which entry 65 listed with three candidate causes.

  • What caught it. Checking where the contour points fall relative to the EQDSK grid, then solving on the separatrix, which removes the edge mismatch at every resolution.

  • Before and after (q difference against the EQDSK; \(I_p\) against 11.77 MA):

    route \(\psi_N\) 0.5–0.9, median \(\psi_N\) 0.9–0.95, median \(I_p\)
    converter contour +3.6% +5.8% +2.5%
    EQDSK separatrix, 80 × 128 +0.2% +0.1% −0.93%

  • What changed. The EQDSK separatrix is the boundary for every ITER case, and the equilibrium is checked against the decision-2 tolerance before any stability run.

  • Blast radius. Entry 65’s claim C-216 is marked superseded by C-221. It was measured correctly for the route it describes, so it is not retracted. No stability result used the first route.

Settings

Each job runs an axisymmetric start, then a health gate, then all n in parallel from that state. The gate requires the minimum of ψ within 1e-3 (relative) of the equilibrium’s axis value, since a deeper minimum signals a blow-up, and positive density and temperature. Two keys that JOREK’s own IMAS input script sets (eta_coul_log_dep, T_min_ZKpar) don’t exist in model303 and are left out.

Growth-rate analysis (scripts/jorek/j5_growth.py). γ is the least-squares slope of ½ ln E of the total (magnetic + kinetic) energy over an energy band. A phase counts as linear only if the two half-windows and the separate magnetic and kinetic fits agree within 2%, over at least 20 points. The band, 1e-15 to 1e-7, was chosen after inspecting the case (a) traces; the first rule, a steady per-step rate over the final segment, cannot work when every run ends in a solver abort and some modes exchange energy between the magnetic and kinetic parts every few steps. Location is the peak of the RMS perturbation over \(\psi_N\) bins: axis if the peak is below 0.05, edge at or above 0.8, otherwise core. Since case (b), it is reported from both the temperature (class) and the flow perturbation (class_u). ωᵢ and γ/ω are estimates computed from the profiles, not JOREK outputs.

Case (a): the EQDSK as given

Pressure from the EQDSK, split into density and temperature with TORAX’s main-ion density at 80 s (D-T, mean mass 2.515 amu). The total axis temperature is therefore high (66.6 keV in case (a) (EQDSK pressure split by TORAX density) against 14.4 keV in case (b) (TORAX at 80 s)C-239): the EQDSK is a higher-pressure state than TORAX at that time, and diamagnetic stabilisation is overstated.

  • Job 1 (Δt = 3) was lost: its axisymmetric start went numerically unstable, and every linear run failed on its first step. The health gate was added after it.
  • Job 2 (Δt = 1) ran 3 h 51 min. Every linear run grew from about 1e-20 over roughly 16 decades and then stopped on JOREK’s GMRES abort (8 of 8 case (a) runs ended on the GMRES abort with exit code 0; a test now checks that such a run is recorded as solver_aborted and not retriedC-230). In this JOREK version linear_run is keep_n0_const: n = 0 is frozen, but the n ≠ 0 equations stay nonlinear, so the matrix drifts as the mode grows and the GMRES iteration count rises step by step until it fails. Fit consistency: half-window and magnetic/kinetic fits agree within 1.1% (tolerance 2%) in all 8 runs; moving the energy band one decade either way changes γ by at most 0.6%C-231.

The job also lost compute to a batch-script bug (about 290 of 1046 core-h: after the last run ended the script waited on its watchdog (an empty wait list became a bare wait); fixed in both job scriptsC-232). The script waited on its background jobs other than the watchdog, wait $(jobs -p | grep -v …). When that list was empty, the command became a bare wait, which also waits for the watchdog, and the watchdog never exits. Both J5 job scripts now skip the wait when the list is empty.

Decision OQ-41. Case (a) is closed on the Δt check: n = 12 and 16 are “converged in Δt, grid not checked”, not quotable; the other six n are “not measured: core or axis mode faster”. The full check moves to case (b), with up to five one-node jobs of ≤ 6 h, each announced.

Case (b) equilibrium

Case (b) is the TORAX ITER hybrid state at 80 s: pressure from TORAX’s density and temperatures, FF′ from TORAX’s current density with the bootstrap current. The FF′ formula reproduces the EQDSK’s own FF′ from the CHEASE geometry to 2.4%.

The first solve gave \(I_p\) +3.7% (10.89 against 10.5 MA) and q +7.8% (median, \(\psi_N\) 0.1–0.5), outside decision 2. The cause is structural: TORAX evolves the current on a fixed CHEASE geometry, so its state is not a Grad–Shafranov equilibrium, and a consistent equilibrium with the same p and j has different flux surfaces and q.

Decision OQ-40 (a). FF′ is multiplied by one factor k so that \(I_p\) = 10.5 MA. Acceptance: \(I_p\) within 1%, and p(\(\psi_N\)) as TORAX’s by construction. The q difference from TORAX is reported as a known inconsistency of the fixed-geometry TORAX state. Rejected: (b) tuning FF′ until q matches, which moves the current profile away from TORAX’s; (c) a self-consistent free-boundary TORAX state first, a larger piece of work.

Convergence of the Grad–Shafranov iteration. Without under-relaxation every case (b) solve stalls (the iteration cycles between two states for all 200 iterations (axis moves about 5 mm, residual about 7e-3); I_p +3.7% at FF’ x 1, −0.0002% at x 0.952, neither convergedC-234): the magnetic axis moves between R 6.2986 and 6.3038 m on alternate iterations. The 2026-10-16 solve already had this (residual 8.2e-3) and it was not flagged then. Case (b)’s FF′ is hollow, because the ramp-up current has not yet reached the core, so the axis is weakly pinned. JOREK’s amix 0.5 (\(\psi_\mathrm{new}\) = 0.5 \(\psi_\mathrm{old}\) + 0.5 \(\psi_\mathrm{solve}\)) converges it to 1e-6 in 43 iterations.

Ceilings

  • No growth rate passes decision 7 yet. Case (a)’s pedestal modes are converged in Δt only; case (b)’s three pedestal modes are converged in Δt at 80 × 128, with the grid check open (OQ-43).
  • The fixed boundary at the separatrix stabilises peeling modes artificially (no vacuum region).
  • The case (b) equilibrium is not TORAX’s: q differs by up to about 14% in the core (median q difference +10.7% (psi_N 0.1–0.5), +3.2% (0.5–0.9), −4.9% (0.9–0.95); q95 4.64 against 4.89, q_min 1.84 against 1.64C-235), by construction of OQ-40 (a).
  • A doubled-grid check of slowly emerging modes costs far more than the approved compute.
  • The grid set-up abort under OpenMP is unexplained; it is to be reported upstream.
